**Ask a weather network a question, get a number, and read the pandas that produced it.**

## The problem

A chatbot that is wrong writes a wrong sentence. An agent that answers by *writing and
running code* is wrong in a more convincing way: the figure comes out of a real
computation, so nobody questions it. Weather data is a good place to feel this, because the
traps are quiet. Sensors drop out and leave blank cells. "Dry spell" can mean consecutive
hours or consecutive days. A groupby over the wrong column still returns a tidy table.

This example puts a smolagents `CodeAgent` in front of three weeks of hourly readings from
five fictional stations and traces every step to Opik, so the code and its console output
are one click away from the answer.

## What you'll build

- `data/readings.csv`: 2,520 rows (5 stations x 21 days x 24 hours) of temperature,
  humidity, wind, rainfall and pressure, with 43 hours of blank sensor readings. It is
  generated by `make_data.py` with a fixed seed and committed, so every run reads the same file.
- A `CodeAgent` on `gpt-4o-mini` that may import only `pandas`. It answers three questions:
  the windiest station-day, total rainfall per station, and the longest dry spell.
- `truth.py`, which computes the same three answers directly with pandas. `main.py` prints
  the agent's answer, the reference, and a `MATCH` / `MISMATCH` verdict.
- Tracing through OpenInference's smolagents instrumentation exported over OTLP to Opik.

## See it in Opik

Open the **smolagents-weather-station-analyst** project. After one run there are three
traces, all named `CodeAgent.run`, one per question.

Open the windiest-day trace. It has 8 spans: the root, three `Step` spans, three
`OpenAIModel.generate` spans (type `llm`) and a `FinalAnswerTool` span. In this run:

- **Generated code.** Click the second `OpenAIModel.generate`. Its output is the model's
  "Thought:" followed by a `<code>` block: a groupby on station and date, a mean of
  `wind_kmh`, an `idxmax`. That is the snippet the agent chose to run.
- **Execution logs.** Click the `Step 2` span. Its output starts with `Execution logs:` and
  then what the code printed, here `Summit Pass 2026-03-11 67.3`. The generated code and
  the printed result are in neighbouring spans, so you can check that the number measures
  what the question asked.
- **Usage.** Each `OpenAIModel.generate` span shows `gpt-4o-mini` and its prompt and completion
  tokens. The prompt count climbs from step to step because every observation is appended to
  the context. No dollar cost yet: see the first gotcha below.
- **Trace input and output.** The trace input holds the briefing plus the question, and the
  output holds the final sentence the agent returned. Both columns are populated.

Models are not deterministic. In an earlier run the same agent answered the dry-spell
question with "Cedar Flats, 20 days, March 2 to March 22". Its dry-spell logic was wrong,
and the `Step 2` execution log (`num_days 20` over a 21-day file) made that obvious in seconds. `main.py` prints `MISMATCH` for that sort of answer. In the run described
above all three matched.

## Run it yourself

1. Put `OPENAI_API_KEY` in `.env` (copy `.env.example`), or in a `.env` one directory up.
   The example also reads the OTLP endpoint from there.
2. Start a local Opik, or point `OTEL_EXPORTER_OTLP_ENDPOINT` at Opik Cloud and add
   `Authorization=<your key>` to `OTEL_EXPORTER_OTLP_HEADERS`.
3. `uv sync`
4. `uv run main.py` (about 45 seconds)
5. Open the `smolagents-weather-station-analyst` project in Opik.

To regenerate the CSV: `uv run make_data.py`. Offline tests:
`env -u OPENAI_API_KEY OPIK_TRACK_DISABLE=true uv run pytest`.

## Poke around

- Edit a question in `agent.py` to be ambiguous ("which station was driest?") and compare how
  the model's code interprets it against what you meant.
- Delete `"pandas"` from `additional_authorized_imports` and rerun. Watch the executor
  reject the import in a `Step` span and the agent try to cope.
- Change the dry-spell definition in the question to hours instead of days and see how the
  generated code changes.
- Set `max_steps=2` and ask the dry-spell question. Find where in the trace the agent runs out of steps.

## Gotchas we hit

**Cost is empty on every span.** Raw OpenInference spans carry `llm.model_name` and token
counts, but no provider Opik recognises, so `total_estimated_cost` stays null even though
usage is there. Opik prices a span only once it knows the provider, and it reads that from
`gen_ai.system`; at this point the example does not set it.

## How it's put together

- `main.py`: loads `.env`, starts tracing, asks the three questions, prints verdicts, flushes.
- `agent.py`: the briefing, the questions, and the `CodeAgent` (pandas-only imports).
- `tracing.py`: OTLP setup and `SmolagentsInstrumentor`.
- `truth.py`: pandas reference answers and a fact-matching grader.
- `make_data.py`: deterministic generator for `data/readings.csv`.
- `tests/test_truth.py`: planted storm, dry spell and sensor gaps; the grader.
- `tests/test_agent.py`: briefing, question list, `ask` with a stub agent.
